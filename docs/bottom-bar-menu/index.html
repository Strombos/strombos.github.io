Bottom-bar menu.

Add your app's own items to the menu that opens when someone right-clicks its bottom-bar button: one interface, one method that returns a list.

New to Triton Apps? Start with Making apps. This page assumes you already have a Main that extends AbstractModule.

What the menu is

Every open app has a button on Triton's bottom bar. Right-click it and a menu opens. Without any work from you, it has Triton's standard items:

  • Bring to Front
  • Bring To, a submenu of screens, only when there are two or more
  • Hide
  • Pin or Unpin
  • Close

Your app can put its own items above those: shortcuts to things people do often, like opening a new tab or starting a recording, without opening the window first. Triton adds a divider line between your items and its own. For a browser with three tabs open, the person sees:

What the person sees 
New Tab
New Incognito Tab
──────────────────
Open Tab         ›
──────────────────
Close All Tabs (3)
──────────────────   added by Triton
Bring to Front
Hide
Pin
Close

Your items can be clickable actions, greyed-out actions, divider lines and submenus that open on hover. You describe them as plain data; Triton draws the menu, in the same style as every other menu on the desktop.

Adding items

Implement shared.BottomBarMenuProvider on your Main and return the items from bottomBarMenuItems(). Here is the Hello app from Making apps with a menu of its own:

Hello/Main.java 
import shared.AbstractModule;
import shared.BottomBarMenuItem;
import shared.BottomBarMenuProvider;
import shared.ModProtection;

import javax.swing.JFrame;
import javax.swing.JLabel;
import javax.swing.SwingConstants;
import java.awt.event.WindowAdapter;
import java.awt.event.WindowEvent;
import java.util.List;

@ModProtection(ModProtection.Policy.ALLOW_MOD)
public class Main extends AbstractModule implements BottomBarMenuProvider {

    private final JFrame frame;
    private final JLabel label = new JLabel("Hello", SwingConstants.CENTER);
    private String greeting = "Hello";
    private int count;

    public Main() {
        frame = echelon.ui.WindowFactory.create("Hello");
        frame.setDefaultCloseOperation(JFrame.DO_NOTHING_ON_CLOSE);
        frame.add(label);
        frame.setSize(480, 320);
        frame.setLocationRelativeTo(null);
        frame.addWindowListener(new WindowAdapter() {
            @Override public void windowClosing(WindowEvent e) { close(); }
        });
    }

    // Runs on every right-click, so "Reset count" stays greyed out at zero.
    @Override
    public List<BottomBarMenuItem> bottomBarMenuItems() {
        return List.of(
                BottomBarMenuItem.action("Say hello", this::sayHello),
                BottomBarMenuItem.action("Reset count", count > 0, this::reset),
                BottomBarMenuItem.separator(),
                BottomBarMenuItem.submenu("Greeting", List.of(
                        BottomBarMenuItem.action("Hello", () -> setGreeting("Hello")),
                        BottomBarMenuItem.action("Hola", () -> setGreeting("Hola")))));
    }

    private void sayHello() { count++; update(); showModule(); bringToFront(); }
    private void reset() { count = 0; update(); }
    private void setGreeting(String g) { greeting = g; update(); }
    private void update() {
        label.setText(count == 0 ? greeting : greeting + " ×" + count);
    }

    @Override public void start()        { frame.setVisible(true); }
    @Override public void bringToFront() { frame.toFront(); }
    @Override public void hideModule()   { frame.setVisible(false); }
    @Override public void showModule()   { frame.setVisible(true); }
    @Override public boolean isVisible() { return frame.isVisible(); }

    @Override protected void onClose()   { frame.dispose(); }
}

Right-click the Hello button and the menu now starts with Say hello, Reset count, a line, and a Greeting submenu, followed by Triton's standard items.

  1. Each item is made with one of the static helpers on BottomBarMenuItem: action, separator or submenu.
  2. The Runnable you pass is what happens when the item is clicked. It runs after the menu has closed.
  3. Clicking an item does not raise your window. If the action should show the app, call showModule() and bringToFront() yourself, as sayHello does.

BottomBarMenuProvider

Interface in package shared, in Triton's jar. Optional: implement it on your Main to add items.

shared/BottomBarMenuProvider.java 
package shared;

import java.util.List;

/**
 * Optional interface for modules that want extra items in the right-click
 * menu of their bottom bar button. Modules that don't implement this get the
 * standard menu (Bring to Front, Bring To when there are several screens,
 * Hide, Pin, Close).
 *
 * <p>The module returns DATA ({@link BottomBarMenuItem}), never a menu
 * component. The bar builds a fresh {@code DesktopPopupMenu} from the list on
 * every right-click and appends the standard items after a separator, so:
 * <ul>
 *   <li>Returning the same cached list every time is safe — the host never
 *       mutates it, so items can't pile up across right-clicks.</li>
 *   <li>If an item's label or enabled state depends on live state, build the
 *       list inside this method so it reflects that state at click time.</li>
 * </ul>
 *
 * <p>Replaces the old {@code JPopupMenu buildBottomBarMenu()} contract.
 * JPopupMenu is not used anywhere in Echelon: it renders unreliably on the
 * non-focusable desktop frame.
 */
public interface BottomBarMenuProvider {

    /**
     * Custom items for this module's bottom bar menu, shown above the
     * standard items. Return an empty list or {@code null} for none.
     */
    List<BottomBarMenuItem> bottomBarMenuItems();
}
MethodWhat it does
List<BottomBarMenuItem> bottomBarMenuItems()Your items, top to bottom. Shown above Triton's standard items, with a line in between. Return an empty list or null for no items; the menu then has the standard items only.

BottomBarMenuItem

Sealed interface in package shared. Its three record types are the only kinds of item there are.

shared/BottomBarMenuItem.java 
package shared;

import java.util.List;
import java.util.Objects;

/**
 * One entry in a module's bottom-bar right-click menu.
 *
 * <p>Plain immutable data — no Swing types. Modules describe WHAT the menu
 * contains; the bottom bar builds a brand-new {@code DesktopPopupMenu} from
 * these on every right-click. Because nothing here is a live menu component,
 * a module that caches its item list cannot make the menu grow, and no
 * {@code JPopupMenu} can leak in through the module API.
 */
public sealed interface BottomBarMenuItem
        permits BottomBarMenuItem.Action, BottomBarMenuItem.Separator, BottomBarMenuItem.Submenu {

    /** A clickable item. {@code onSelect} runs on the EDT after the menu closes. */
    record Action(String label, boolean enabled, Runnable onSelect) implements BottomBarMenuItem {
        public Action {
            Objects.requireNonNull(label, "label");
            Objects.requireNonNull(onSelect, "onSelect");
        }
    }

    /** A divider line. Leading, trailing and doubled separators are dropped by the host. */
    record Separator() implements BottomBarMenuItem {}

    /** A hover-to-expand submenu. */
    record Submenu(String label, List<BottomBarMenuItem> items) implements BottomBarMenuItem {
        public Submenu {
            Objects.requireNonNull(label, "label");
            items = List.copyOf(items);
        }
    }

    Separator SEPARATOR = new Separator();

    static BottomBarMenuItem action(String label, Runnable onSelect) {
        return new Action(label, true, onSelect);
    }

    static BottomBarMenuItem action(String label, boolean enabled, Runnable onSelect) {
        return new Action(label, enabled, onSelect);
    }

    static BottomBarMenuItem separator() {
        return SEPARATOR;
    }

    static BottomBarMenuItem submenu(String label, List<BottomBarMenuItem> items) {
        return new Submenu(label, items);
    }
}

Helpers (use these)

MethodWhat it makes
action(String label, Runnable onSelect)A clickable item. Clicking it closes the menu, then runs onSelect.
action(String label, boolean enabled, Runnable onSelect)The same, but greyed out and not clickable when enabled is false. onSelect is still required; pass () -> {} for an item that is only ever a label.
separator()A divider line. Always returns the same SEPARATOR object.
submenu(String label, List<BottomBarMenuItem> items)An item that opens a second menu on hover. The list is copied when you call this, so later changes to your list don't show.

Types and fields

MemberWhat it is
record Action(String label, boolean enabled, Runnable onSelect)A clickable item. label is the text shown. enabled = false shows it greyed out. onSelect runs on the Swing thread after the menu closes. label and onSelect must not be null.
record Separator()A divider line. Triton drops one at the start or end of a list, and turns two in a row into one.
record Submenu(String label, List<BottomBarMenuItem> items)A submenu. label must not be null. items is copied with List.copyOf, so it must not be null or contain null.
Separator SEPARATORThe shared divider instance that separator() returns.

There is no item type for icons, check marks, keyboard shortcuts or hidden items. To hide an item, leave it out of the list (see Building the list). To show on/off state, put it in the label, for example "● Recording".

Building the list

  • Order: the menu shows your items in list order, top to bottom. Submenus show theirs in their own list's order.
  • Greyed out: an action with enabled = false is shown but can't be clicked. Use it when the item makes sense but can't run right now, like Reset count at zero.
  • Hidden: an item that doesn't apply right now is simply not added. Build the list with ifs, as below.
  • Lines: put separator() between groups. Triton removes a line at the start or end and turns two in a row into one, so a line next to an item you left out does no harm.
  • Submenus: a submenu with no items (or only lines) isn't shown. Submenus can go three levels deep; a submenu nested deeper than that is dropped.
  • Live or cached: Triton never changes your list and builds a new menu each time, so returning the same fixed list on every call is fine. If a label or enabled depends on what the app is doing, build the list inside bottomBarMenuItems() so it is current at the moment of the right-click.
Example · items that come and go 
@Override
public List<BottomBarMenuItem> bottomBarMenuItems() {
    List<BottomBarMenuItem> items = new ArrayList<>();
    String label = recording ? "Stop recording" : "Start recording";
    items.add(BottomBarMenuItem.action(label, this::toggleRecording));
    if (lastFile != null) {
        items.add(BottomBarMenuItem.separator());
        String name = lastFile.getName();
        items.add(BottomBarMenuItem.action("Open " + name, this::openLast));
    }
    return items;
}

The label of the first item follows recording, and the second item only appears once there is a lastFile. Use ArrayList rather than List.of when the list is built step by step.

When Triton asks

WhenWhat happens
Someone right-clicks your app's bottom-bar buttonTriton calls bottomBarMenuItems(), on the Swing thread, right before the menu appears. It asks again on every right-click and never keeps your items between menus.
Your method returnsTriton builds a new menu: your items, a line, then the standard items. With no items (or only lines), there's no extra line.
Someone clicks one of your itemsThe menu closes, then onSelect runs on the Swing thread.
The menu is closed without a clickNothing. None of your code runs.

Because bottomBarMenuItems() runs on the Swing thread while the person waits for the menu, keep it fast: read fields, don't read files or go to the network. Do the work in onSelect instead, and start a thread there for anything slow.

When something goes wrong

  • If bottomBarMenuItems() throws, Triton writes the error to its log and opens the menu with the standard items only.
  • If an onSelect throws, Triton writes the error to its log. The bottom bar and the rest of the desktop keep working.

When your items don't appear

When one app has two or more buttons on the bar, for example its Dock pin and an open window, or two open windows, Triton folds them into one group button. Right-clicking a group button shows the group's own menu (Launch new instance, Pin to Dock or Unpin from Dock, Close window) and doesn't ask your app for items. Your items show again once the app is back to a single button.

A real app: Meridian

Meridian, Triton's web browser, uses this menu. Its bottomBarMenuItems() builds the list fresh on every right-click:

  • While the browser engine is still starting, it returns a single greyed-out Browser is loading… item and nothing else.
  • After that: New Tab and New Incognito Tab, a line, an Open Tab submenu with one item per tab (the current one marked with ●), and Close All Tabs (3) with the live count.
  • With no tabs open, the submenu is replaced by a greyed-out No open tabs.
  • The actions that need the window call bringToFront() after doing their work.

That's the pattern to copy: a few common actions at the top, live state in the labels, and greyed-out items to explain why something isn't available.

Common mistakes

MistakeWhat happens · fix
Still using the old JPopupMenu buildBottomBarMenu()Ignored: the menu has the standard items only, and the Triton log says still has buildBottomBarMenu() (JPopupMenu) — ignored. Implement BottomBarMenuProvider instead.
Building the list once in the constructor when a label depends on stateThe menu keeps showing the old label or count. Build the list inside bottomBarMenuItems().
Slow work inside bottomBarMenuItems()The menu opens late and the desktop stops responding meanwhile. Only read fields there; do the work in onSelect.
Long work inside onSelectIt runs on the Swing thread, so the desktop freezes until it ends. Start a thread or a SwingWorker for it.
A null label or action, or a null inside a submenu's listNullPointerException while building the list, so none of your items appear. Use () -> {} for an action that does nothing, and leave out items you don't want.
Expecting enabled = false to hide an itemIt shows greyed out. To hide it, don't add it.
An empty submenuNot shown at all. Leave the submenu out, or put a greyed-out item in it that says why it's empty.
Expecting a click to bring the window forwardClicking your item only runs onSelect. Call showModule() and bringToFront() in it when the action needs the window.
Testing with the app pinned to the Dock, or with two windows openThe bar shows a group button, and its menu has no app items (see When Triton asks). Test with one window and no Dock pin.
Adding your own Close, Hide or Pin itemsTriton always adds those below yours, so they'd appear twice. Add only what is specific to your app.
Changing a list after passing it to submenu(…)The submenu keeps the copy made at that moment. Finish the list first, then call submenu.
