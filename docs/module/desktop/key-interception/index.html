Key Interception.

Triton sees every key you press before your operating system or any app does. That is how the Desktop takes over the Windows key, the keyboard's Home button and other shortcuts, and how you can add, remap or block keys of your own.

This list may be out of date. Triton changes often, and the keys on this page may not match your build yet. Echelon Center → Keybinds always shows the keys your Triton uses.

What it does

Key Interception starts with the Desktop. For every key you press, Triton checks its list of bindings. A binding can do one of four things:

BindingWhat happens
ActionTriton runs one of its actions, such as opening the launcher. The key goes no further.
RemapTriton sends a different key or shortcut instead.
BlockThe key does nothing.
PassThe key goes to your operating system as usual. Use it to give a key back.

Keys with no binding always go straight through to the operating system and your apps.

A binding can be limited to the Desktop: it then only works while the Triton Desktop is in front, so the same key still works as usual inside app windows. The tables below say Desktop only for these.

In the tables, Win means the Windows key, the Command key on macOS and the Super key on Linux.

All operating systems

KeyDoes
Win or Super (tap it on its own)Open Triton home: shows the Desktop if it was hidden and opens the launcher. Action triton.home.
Keyboard Home button (BROWSER_HOME)Open Triton home. Action triton.home.
Ctrl+Alt+Shift+F12Pause or resume Key Interception: while paused, every key goes back to the operating system. Locked: you can't change or remove this one. Action triton.keys.pause.
↑ ↓ ← →Desktop only. Move the tile selection. Actions triton.desktop.select.up, .down, .left, .right.

EscDesktop only. Clear the tile selection. Action triton.desktop.select.clear.

Windows and Linux

KeyDoes
Win+TOpen the Triton Terminal. Action triton.terminal.
Win+MMove the active window to another screen. Replaces Windows' own "minimize all". Action triton.window.moveToScreen.
Win+DHide all apps and show the Desktop; press again to bring them back. The Desktop then takes the arrow keys and Enter. Action triton.desktop.hideApps.

Windows only

KeyDoes
Ctrl+EscOpen Triton home, like the Win tap. Action triton.home.
Win+S, Win+QOpen or close the launcher, for search. Action triton.launcher.
Win+N, Win+AOpen or close the notification centre. Action triton.notifications.

Blocked keys

On Windows only, these do nothing in Triton, because Windows would bring up its own taskbar or one of its panels over the Desktop:

KeyWindows would open
Win+0 … Win+9A taskbar app
Win+BThe taskbar's notification area
Win+XThe Start button's menu
Win+TabTask View
Win+WWidgets
Win+,Desktop peek

Every other Win shortcut still goes to the operating system. To get a blocked key back, give it pass (see settings.properties).

The Win key

Triton lets the Win key go down as normal, so shortcuts it doesn't take over keep working. When you tap Win on its own, or use it in a shortcut Triton takes, Triton stops the operating system from reacting to it: Windows' Start menu and the GNOME or KDE overview don't open.

Shift gives Win back. When Shift is held with Win, Triton leaves that press to the operating system, so its own Win+Shift shortcuts work. Shortcuts you bind yourself with WIN+SHIFT+… still work. Turn this off in Keybinds or with:

triton.keys.shiftPassesWin=false

Keybinds

Open Echelon Center → Keybinds to see and change every binding. It has four tabs:

TabWhat's there
GeneralTurn Key Interception on or off, pause it, give Win to the OS when Shift is held, and whether the engine is running.
ShortcutsKeys that run an action. Add shortcut records a new one.
RemapsKeys that send another key. Add remap.
BlockedKeys that do nothing, and keys given back to the OS. Block keys.

A change you make there is saved as a line in settings.properties, below.

Your own keys in settings.properties

Your bindings are lines in settings.properties, in Triton's main folder echelon. Each line is one key:

triton.keys.map.<KEY>=<what it does>
What it doesMeaning
action:<id>Run an action
key:<KEY>Send this key or shortcut instead
blockDo nothing
passGive the key back to the operating system

Add @desktop to the key to make the binding Desktop only.

Example · settings.properties 
# Give the Win key back to the Start menu
triton.keys.map.WIN=pass

# Win+E opens the launcher
triton.keys.map.WIN+E=action\:triton.launcher

# Caps Lock becomes Ctrl
triton.keys.map.CAPSLOCK=key\:LCTRL

# F5 runs an action, but only while the Desktop is in front
triton.keys.map.F5@desktop=action\:my.refresh
  • Your line replaces Triton's own binding for the same key, except the locked pause key.
  • Triton saves the : after action or key as \:, as .properties files do. Writing a plain : works too.

Per operating system

SystemNeedsBuilt-in keys

If your system can't run it, Key Interception stays off and the rest of Triton works as usual. The Engine row in Keybinds then says Needs setup.

Pause or turn it off

  • Pause: press Ctrl+Alt+Shift+F12. Every key goes back to the operating system until you press it again.
  • Turn off: switch off Intercept keys in Keybinds, or add this line to settings.properties:
triton.keys.enabled=false
