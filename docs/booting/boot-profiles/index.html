Boot profiles.

Every time Triton starts, it boots a profile. The profile decides which parts of Triton load and what opens when booting is done. The default profile ends on the Desktop.

New to Triton? Leave the defaults alone: Triton boots the Desktop on its own. This page explains what happens on the way there, and how to pick something else.

What a boot profile is

A boot profile is a folder in echelon/boot/profiles/ with two files in it:

  • boot.bsp, the Boot Script Profile. It names the profile, lists the components it loads and says what to open at the end.
  • logo.png, the icon shown on the boot screen.

Triton ships with three profiles:

ProfileOpensWhat it loads
Triton Desktop
triton_desktop_lite		DesktopThe Desktop essentials: the bottom bar, theme, launcher, widgets and control center. The default.
Triton Desktop (MAX)
triton_desktop_max		DesktopThe full desktop environment, with the Troy Assistant.
Triton Terminal
triton_terminal		TerminalA lightweight, terminal-only session: no Desktop, no widgets. See Terminal.

The two Desktop profiles are variants in one group, desktop. A group shows as one icon on the boot screen. Hold Shift to see all its variants.

How Triton boots

Booting runs in four phases, in this order:

  1. Core. Triton's core services start. They are the same for every profile.
  2. Select profile. You pick a profile, or Triton picks the default for you.
  3. Components. The components the profile lists load. On a Desktop profile, the Desktop is built behind the boot screen.
  4. Launch. The profile's module opens: the Desktop, or the Terminal.

Press F12 on the boot screen to open the diagnostics drawer: the console, security checks and a report of everything that booted.

Choosing a profile

The boot screen has two styles:

StyleWhat you see
Fast LoadingThe default. A full-screen loader boots the profile you used last, with no questions. To choose another one, press Esc while the loader shows ESC · BOOT OPTIONS.
Modern BootA window with the row of profile icons. The default profile counts down, 5 seconds unless its boot.bsp says otherwise, then starts on its own. Any key or click stops the countdown.

On the row of profile icons:

KeyAction
← → or ↑ ↓ or TabMove to the previous or next profile.
1 … 9Jump straight to that profile.
Home EndJump to the first or last profile.
Enter, Space or a clickStart the selected profile.
Hold ShiftShow the variants of the selected group. ← → picks one; release Shift to close them.
F12Open or close the diagnostics drawer.

After you shut down the Desktop, Triton goes back to the row of profiles in a window and waits for you to pick. There is no countdown then, so it never reopens what you just closed.

The default profile

The profile you started last becomes the default the next time Triton boots. Triton keeps it in echelon/boot/last_use.properties.

  • On the very first boot, the profile with default = true in its boot.bsp is the default: Triton Desktop.
  • To always start from the boot.bsp defaults instead, set remember = false in last_use.properties.

To switch between Fast Loading and Modern Boot, open Echelon Center → System → Boot Options and pick a Boot Screen. Or edit echelon/boot/boot.properties:

echelon/boot/boot.properties 
style = modern     # or: fast

The style applies the next time Triton boots.

Writing a boot.bsp

To add a profile, make a folder in echelon/boot/profiles/ and put a boot.bsp and a logo.png in it. The folder name is the profile's id. This is the shipped Triton Desktop profile, shortened:

echelon/boot/profiles/triton_desktop_lite/boot.bsp 
[profile]
id          = triton_desktop_lite
name        = Triton Desktop
description = Desktop essentials — chrome, theme, launcher, control center
module      = Desktop
group       = desktop
logo        = logo.png
default     = true
order       = 0
countdown   = 5

required_component = [
    desktop.component.*,
    desktop.theme.*,
    desktop.widget.*,
    !desktop.component.dock,
]
KeyMeaning
idThe profile's id. Defaults to the folder name.
nameThe name on the boot screen.
descriptionOne line shown under the selected icon.
moduleWhat opens at the end: Desktop or Terminal.
groupProfiles with the same group share one icon. Optional.
logoThe icon file, next to boot.bsp. Defaults to logo.png.
defaulttrue on the one profile to start on the first boot.
orderWhere the profile sits in the row, lowest first.
countdownSeconds before the default starts on its own. 0 waits for a click.
accentA highlight colour, for example #FF4D12. Optional.
required_componentThe components to load. See below.

Each required_component is an exact component id, or a pattern like desktop.* for a whole subtree:

  • Triton's core components, core.*, always load. You never need to list them.
  • A ! in front excludes a component, for example !desktop.component.dock. Exclusions always win.
  • Write one per line, separate them with commas, or use a [ … ] block. They all add up.

Lines starting with # or // are comments. To remove a profile, delete its folder or add disabled = true. If the folder holds no profile at all, Triton puts the shipped ones back on the next boot.

Don't load desktop.* components in a profile that opens the Terminal. They need the Desktop, and they fail without it.

From boot to the Desktop

With a Desktop profile, the last phases lead straight into the Desktop:

  1. While the components load, Triton builds the Desktop out of sight. Modern Boot shows a live preview of it.
  2. At launch, the sign-in screen rises over the boot screen.
  3. Once you sign in, the Desktop fills the screen. Each extra screen gets a Desktop of its own.

Closing the Desktop asks you to confirm a shutdown, then takes you back to the row of profiles.
